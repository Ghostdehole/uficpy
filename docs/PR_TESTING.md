# 测试 PR 版本

PR 的 **Test** 工作流通过后，会生成 `uficpy-pr-<PR号>-<构建次数>` 附件，保留 14 天。它包含 ARM64 / ARMv7 后端、管理插件和校验文件，不会发布到正式 Releases，也不会改变国内备用源。

在 PR 页打开 **Checks → Test → Details**，进入对应 Actions 运行记录，下载底部 **Artifacts** 中的附件。需要登录 GitHub。

## 安装测试版

1. 在现有管理插件中导出配置留作备份。配置含访问令牌，请保存在自己手中。
2. 解压 Actions 附件，在 UFI-TOOLS 中导入其中的 `uficpy_plugin-v2.3.0.js`，替换旧插件。
3. 在 **管理与诊断 → 诊断 → 设备架构** 中确认需要 ARM64 还是 ARMv7 包。选择对应 tar.gz，并用附件里的 `SHA256SUMS` 核对文件摘要。
4. 通过自己现有的设备文件管理方式，将该 tar.gz 放到 `/data/local/tmp/uficpy-pr/`。不要解压到正在运行的 `/data/uficpy` 中。
5. 在设备的 Root 终端中执行以下命令。示例为 ARM64，ARMv7 请将文件名替换为 `uficpy-armv7.tar.gz`。

```sh
cd /data/local/tmp/uficpy-pr
sha256sum uficpy-arm64.tar.gz
```

确认输出与附件校验文件里对应条目一致后，在一个尚不存在的目录中解压安装：

```sh
mkdir extracted
tar -xzf uficpy-arm64.tar.gz -C extracted
sh extracted/install.sh
```

安装脚本保留现有配置和访问令牌，先验证新程序可以执行，再替换旧后端；旧目录会保留为备份。刷新管理插件，确认后端显示 `2.3.0`，从 **新窗口** 打开播放器。

测试期间不要点击 **安装 / 更新**：该按钮仍然读取正式发布源，可能把测试版换回正式版。也不要将 PR 的清单同步到正式下载站。

## 建议检查

- 用自己的小型 APK 测试首次安装和同签名更新；签名不匹配时应显示 Android 错误，旧应用仍在。
- 传一个中文文件名的普通文件，确认保存位置；再次上传同名文件应报冲突，原文件不被覆盖。
- 上传未结束时取消，观察错误提示与清理；安装开始后不要强制重试，先确认设备上的结果。
- 测试剪贴板、屏幕开关、旋转和通知栏；停止服务后确认物理屏幕能够恢复。
- 开启音频后测试本机 Android 版本和应用是否允许采集；设备不支持时，视频与控制应仍可使用。
- 录制一小段视频并下载 MP4；目前没有音轨。再检查触控、文字、重连和只读模式。

回退时，先停止测试版服务，把安装测试版之前导出的配置恢复到 `/data/uficpy/config.json`，再使用上一条正式 Release 的对应后端包，按相同方式运行 `install.sh`，最后换回旧版管理插件。新配置包含 `audio_source`，2.2.3 及更早版本不认识这个字段，因此不能直接携带测试版配置回退。不要用“全新安装”代替配置恢复；请保留原始备份，直到确认旧版重新运行。
