# 测试

测试环境需要 Go 1.27、Node.js 24、Python 3、FFmpeg 和 Chrome。

```sh
npm ci
npx playwright install --with-deps chrome
sh scripts/test.sh
```

## 覆盖范围

- Go：配置、HTTP / WebSocket、权限、触点隔离、按键释放、采集进程、TLS 和并发竞态。
- JavaScript：视频封装、控制报文、输入状态和浏览器存储。
- Python：安装、回滚、卸载、服务进程、安装前执行检查和双架构发布包。
- Chrome：MSE / WebCodecs 播放、多客户端、触控、滚轮、键盘、文字粘贴，以及插件弹窗、配置操作、架构选择和备用下载源。

媒体测试比较原始 H.264 与 fMP4 解码后的帧哈希，检查封装过程是否改变画面。浏览器测试使用真实 Go 服务和模拟采集进程，不依赖 Android 设备。

服务进程测试需要 Linux `/proc` 访问权限；受限环境会跳过对应测试。可以通过 `GO` 指定 Go 可执行文件，通过 `UFICPY_CHROME` 指定 Chrome 路径。

`UFICPY_UFI_UTILS` 和 `UFICPY_UFI_REQUESTS` 可分别指向 UFI-TOOLS 的 `utils.js` 和 `requests.js`，用于宿主接口兼容性测试。`UFICPY_UFI_MAIN` 可指向宿主 `main.js`，验证版本化文件仍按固定插件标识覆盖更新。

## 设备测试

自动测试不能覆盖 Android 固件、MediaCodec 编码器和 iPhone Safari 的全部差异。设备上需检查画面、控制、重连、自启、空闲停止采集，以及长时间运行的温度和耗电。

FPS、缓存和 RTT 各自反映局部状态，不能直接作为画面端到端延迟。音量键测试有恢复出厂风险，不包含在自动测试中。

## 2.3.0 审阅与真机验证

本分支新增 APK 安装、普通文件上传、手动双向剪贴板、设备快捷控制、PCM 音频和原码流录制。模拟采集与命令替身可以检查报文、权限和失败路径，但不能证明 Android 包管理器、固件音频权限或物理屏幕控制已经通过真机测试。PR 中应记录实际运行的检查及尚未完成的设备验证。

合并前建议在测试设备上完成以下操作：

| 项目 | 验证内容 |
| --- | --- |
| APK | 首次安装、同签名更新后数据保留、签名冲突及空间不足提示；安装失败不卸载原应用 |
| 上传 | APK选择/拖放、普通文件保存、同名文件、中断、超限与只读模式；检查临时文件清理 |
| 剪贴板 | 中文与换行、读取空内容、设置后手动粘贴；HTTP与HTTPS下的文本框回退；多个页面不互收剪贴板内容 |
| 设备控制 | 通知/快捷设置/收起、旋转、正确及错误包名；临时熄屏后仍可操作、最后一个观看连接结束时恢复屏幕 |
| 音频 | Android11解锁启动、设备输出、麦克风、手动启声、静音、断线；不支持设备上视频和控制继续运行 |
| 录制 | 等待关键帧、停止下载、播放保存的MP4、旋转和断线分段、到限停止；确认文件无音轨 |
| 回归 | 多客户端、画面和触控、升级保留配置、无人观看时停止采集、自启与卸载 |

在记录结果时附设备型号、固件/Android版本、浏览器版本、画质参数和连续运行时间。旧版的测试结论不自动代表新增功能已经通过。
